# hopo 2.6 plan: smoother app, taskbar icon, top-level right-click menu, Shift+S ring, Android app

Status: plan only. Nothing here is built yet. Each part ships as its own branch and PR with its own change record, in the order below (smallest and safest first).

## 1. Make the app stop lagging (Windows)

What the code shows today (source/UI):
- Home redraws its rings every frame through `CompositionTarget.Rendering` (HomeAndSendPages.cs:227), even when nothing changes.
- Several large blurred shadows (`DropShadowEffect` with BlurRadius 60 and 80 on the send sheet, HomeAndSendPages.cs:184-185, plus one per device dot). WPF draws these slowly, and they get slower on big windows and high-DPI screens.
- Many animations run forever (ripples, pings, glows), even when the window is hidden in the tray.
- Every transfer progress tick, phone poll and discovery announcement rebuilds the whole current page (AppShell.cs:112-119). During a transfer, Home is rebuilt several times a second.

Steps:
- [ ] Measure first: time each page `Refresh()` and the per-frame `Frame` work, with a transfer running and a phone connected. Record the numbers in the record.
- [ ] Rings: draw them once and animate with cheap transforms (rotation) instead of redrawing every frame. Cap the frame rate.
- [ ] Shadows: replace the big blurred `DropShadowEffect`s with pre-rendered soft shadows (gradient borders), the same trick already used for the Home glow.
- [ ] Pause every animation and the per-frame handler when the window is minimised, hidden in the tray or not on Home.
- [ ] Refresh only what changed: update progress bars and device dots in place, and batch updates to at most a few per second instead of rebuilding the page.
- [ ] Respect Windows "Animation effects" off: no motion at all.
- [ ] Re-measure and record the before and after numbers. Target: Home under 5% CPU when idle, and no stutter while sending.

## 2. Fix the missing taskbar icon (Windows)

What the code shows today:
- The window sets its own taskbar identity ("hopo.LocalFileSharing" / "hopo.Admin") with an icon taken from the exe (WindowsIntegration.cs:130).
- The Start menu and desktop shortcuts made by the MSI do not carry that same identity, so Windows may not connect the window to a shortcut with an icon.
- Lantoss.ico has 16, 32, 48 and 256 px images but no 24 px, which is the taskbar size at 100% scale.

Steps:
- [ ] Reproduce on this PC with the installed 2.5.3, both apps, pinned and unpinned, and at 100% and 125% scale.
- [ ] Give the MSI shortcuts the same app identity as the window (`System.AppUserModel.ID`), so Windows ties the window, shortcut and icon together.
- [ ] Add 20, 24, 40 and 64 px images to the icon.
- [ ] Check that the relaunch icon resource points to the installed exe, not a temporary path.
- [ ] Verify after install and after upgrade from 2.5.3, including clearing Windows' icon cache once.

## 3. "Share with hopo" in the first right-click menu (Windows 11)

Why it is under "Show more options" today: Windows 11 only puts apps in the first (modern) menu if they register through a packaged app identity (a "sparse package" with an `IExplorerCommand` handler). hopo 2.3 had this (source/Explorer, ExplorerPackage.cs). 2.4 removed it because the package must be signed by a certificate that Windows trusts, and setting that up needed an administrator step.

Plan:
- [ ] Bring back the native Explorer command (source/Explorer/LantossExplorer.cpp, now pointing at hopoUsers.exe) with a submenu: "Send with hopo" > each paired PC and phone, plus "Choose…".
- [ ] Package it as a signed sparse package that the MSI registers, so it appears in the first menu.
- [ ] Keep the classic menu entry as a fallback (Windows 10, or if the package cannot register).
- [ ] The menu reads a small cached device list, so right-click stays instant and never opens the data store.

**Decision needed (signing):**
- **(a) Self-signed certificate.** Free. The installer adds it to "Trusted People" on that PC, which needs one administrator (UAC) prompt during setup. Fine for family PCs.
- **(b) Paid code signing.** Azure Trusted Signing is about US$10 a month; a classic code-signing certificate is about US$100–300 a year. No extra prompt, and it also removes the SmartScreen warning. Needs identity verification.

## 4. Shift+S: send the selected files with a device ring (Windows)

How it works:
1. Select files or folders in File Explorer and press the shortcut.
2. A round ring opens at the mouse pointer, with connected PCs and phones placed around it (the same look as Home). A count shows the files and their total size.
3. Click a device, press its number key, or use the arrow keys and Enter. Esc or a click outside closes it.
4. The send starts as usual, and the receiver still approves.

Build steps:
- [ ] The running app (also in the tray) watches for the shortcut, but only while File Explorer or the desktop is the active window and no text box (rename, search, address bar) has focus. Everywhere else the keys pass through untouched.
- [ ] Read the current Explorer selection through the Windows Shell (the active Explorer window's selected items).
- [ ] New ring overlay window: transparent, always on top, sized to the ring, keyboard and screen-reader friendly, and drawn without the costly effects from part 1.
- [ ] A setting to turn the shortcut off or change it.
- [ ] Tests for the selection reader and the key filter (no capture while typing).

**Decision needed (shortcut):** Shift+S on its own also types a capital S, and in Explorer it jumps to files starting with S.
- Recommended: **Ctrl+Shift+S**, only in Explorer and on the desktop.
- Alternative: plain **Shift+S**, only in Explorer and on the desktop when no text box is focused. This replaces Explorer's jump-to-S for that key.

## 5. Android app

Approach: build it in C# with Avalonia, the same toolkit as the Mac and Linux app, so it reuses the existing transfer, pairing, encryption and sync code (Lantoss.Core) instead of rewriting the protocol. Android phones then pair with PCs exactly like another PC: same code comparison, same encryption, same approvals.

First version (MVP):
- [ ] Find PCs on the Wi-Fi, pair with the matching code, and send and receive files and text with paired PCs.
- [ ] "Share to hopo" in Android's share sheet (photos, files, links from any app). This is Android's version of right-click.
- [ ] Received files go to Downloads/hopo, and show up in the gallery or Files app.
- [ ] Transfers keep running with the screen off, with a progress notification (Android foreground service).
- [ ] Android permissions: nearby Wi-Fi devices and local network discovery, notifications, and media access only when used.
- [ ] Home screen with the device ring, Transfers, and Text & links.

Later versions: shared folders, two-way folder sync, and a receive-only mode that hosts a phone-to-phone page.

Code changes needed first:
- [ ] Split the browser portal out of the transfer engine, because ASP.NET Core (Kestrel) does not run on Android. The Android app does not host the phone page.
- [ ] A file-based device key on Android (the Mac/Linux path already does this).
- [ ] Android-specific discovery: hold a multicast lock while scanning.
- [ ] New project source/Android (Avalonia.Android) and a build.ps1 mode to build a signed APK.

**Decisions needed:**
- **One-time download.** Building Android apps needs the .NET Android workload, the Android SDK and a Java JDK, about 3–4 GB in total, downloaded once into work\ and reused offline after that. Nothing else can be reused, because no Android tools are on this PC yet.
- **Distribution.**
  - APK on GitHub Releases: free, but users allow "install unknown apps" once.
  - Google Play: US$25 one time, plus app review and a privacy form.
- **Signing key.** A release keystore is created once and must be kept safe and backed up. Losing it means users must uninstall to update.

## Order and versions
1. Lag fixes, then the taskbar icon: hopo 2.6.0.
2. Shift+S ring: hopo 2.6.0 or 2.6.1.
3. Windows 11 top-level menu: after the signing decision.
4. Android MVP: hopo 2.7.0, after the download and distribution decisions.
